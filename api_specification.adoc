== Abstract

This document is the official technical specification of the **{spec-name}** standardised
by the **{organization}** ({short-name}).
It defines, in a language-agnostic way, the interfaces, classes, enumerations, exceptions, structural
relationships and behavioural requirements that any conforming implementation of the {spec-name} MUST satisfy.

The {spec-name} extends the *Terminal Reader API* with the abstractions required to manipulate *storage cards*
(Mifare Ultralight, Mifare Classic 1K/4K, ST25/SRT512). It exposes a block-oriented memory image, an authentication
mechanism for Mifare Classic and a transaction manager that batches read and write commands.

== Introduction

=== Purpose

The {spec-name} defines the contracts required to:

* select storage cards through the *Terminal Reader API* selection mechanism,
* perform block-level read and write operations,
* expose card-specific metadata (product type, UID, system block),
* authenticate against Mifare Classic sectors using Key A or Key B.

Conforming implementations MUST guarantee interoperability with [CNA-TR-API] reader implementations.

=== Scope

This specification covers:

* the factory used to instantiate the public types of the API,
* the abstract representation of a storage card and its product types,
* the card-selection extension used to enrich a selection scenario with storage-card commands,
* the transaction manager used to exchange APDUs with the selected card,
* the family of storage-card-specific exceptions.

The following topics are *out of scope*:

* the wire-level protocols specific to each storage card technology,
* the management of cryptographic key material for Mifare Classic authentication.

=== Conformance

A software product conforms to this specification if and only if:

. it implements every interface and class defined in <<sec_specification>> with the operations and semantics
  prescribed in this document,
. it raises exceptions exclusively of the types defined in <<sec_exceptions>> for the situations described,
. it preserves the structural and behavioural relationships described in <<sec_architecture>>.

Throughout this specification, the key words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, **RECOMMENDED**,
**MAY** and **OPTIONAL** are to be interpreted as described in **RFC 2119** and **RFC 8174** when, and only when,
they appear in all capitals.

In conformance with RFC 2119, **SHALL** is equivalent to **MUST**; this specification uses **MUST** exclusively in
order to avoid ambiguity.

== Terms, Definitions and Abbreviations

=== Terms and Definitions

[cols="1,4", options="header"]
|===
| Term              | Definition

| Block             | Smallest addressable storage unit on a storage card. The block size depends on the card product type.
| Sector            | Group of blocks sharing the same access conditions on a Mifare Classic card.
| System Block      | Block containing card-specific metadata and configuration data. Available on selected card types only.
| Storage Card      | Card whose primary purpose is to store binary data in addressable blocks, by opposition to a Calypso or generic application card.
| Mifare Classic    | NXP Mifare Classic 1K/4K family of contactless storage cards using sector-based authentication.
| UID               | Unique IDentifier of the card.
| OTP               | One-Time-Programmable memory area whose bits can only transition from `0` to `1`.
|===

[[type_MifareClassicKeyType]]
==== MifareClassicKeyType

[cols="1h,4", grid=rows, frame=ends]
|===
| Kind     | Enumeration
| Package  | `storagecard`
| Purpose  | Enumerates the Mifare Classic key types used for authentication.
|===

Mifare Classic cards support two types of keys per sector. Each sector can be protected independently by these
keys, allowing fine-grained access control.

[cols="1,4", options="header"]
|===
| Value   | Description

| `KEY_A` | 1.1.0
| Primary key used for authentication to a Mifare Classic sector. In most configurations, Key A has read/write
  permissions while Key B may have restricted permissions.

| `KEY_B` | 1.1.0
| Secondary key used for authentication to a Mifare Classic sector. Key B is often used for restricted operations
  or read-only access, depending on the sector's access conditions.
|===

[cols="1h,4", grid=rows, frame=ends]
|===

| Description | Returns the number of blocks in the main memory area of the card. Additional *system* blocks MAY exist and are not included in this count.
| Returns     | The number of blocks.
| Throws      | None.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `getBlockSize() -> integer`
| Description | Returns the size of each block in bytes.
| Returns     | The block size.
| Throws      | None.

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `hasSystemBlock() -> boolean`
| Description
| Indicates whether the product type exposes an accessible system block. For ST25/SRT512 cards, the system block is
  accessible at address 255. When a system block is available, it MAY be read using the appropriate `prepare*`
  operations during selection or transaction processing.
| Returns     | `true` if the product type exposes a system block, `false` otherwise.
| Throws      | None.

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `hasWriteAcknowledgment() -> boolean`
| Description
| Indicates whether the product type provides a reliable acknowledgment after write operations. When this operation
  returns `true`, a successful write response guarantees that the data has been correctly stored. When it returns

| Returns     | `true` if the card provides a reliable write acknowledgment, `false` otherwise.
| Throws      | None.
|===

|===
| Signature   | `hasAuthentication() -> boolean`
| Description
| Indicates whether the product type requires authentication before read/write operations. When this operation
  returns `true`, the application MUST authenticate the targeted sector before issuing read or write commands.
| Returns     | `true` if the card requires authentication, `false` otherwise.
| Throws      | None.
|===

===== Operations

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `getProductType() -> ProductType`
| Description | Returns the product type of the storage card.

| Throws      | None.

[cols="1h,4", grid=rows, frame=ends]

| Signature   | `getUID() -> byte array`
| Description | Returns the unique identifier (UID) of the storage card.
| Returns     | A `byte array` containing the UID.
| Throws      | None.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `getSystemBlock() -> byte array`
| Description
| Returns the system block when it has been read. The system block contains card-specific metadata and
  configuration data. This feature is specific to ST25/SRT512 cards.

  The system block MUST have been previously read using `prepareSt25ReadSystemBlock()`.
| Returns     | A `byte array` containing the system block data, or `null` if the system block has not been read yet.
| Throws      | `UnsupportedOperationException` -- if the current card type does not support system block access.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `getBlock(blockAddress: integer) -> byte array`
| Description
| Returns the data block at the specified block address. If the block has not been previously read, the returned
  array MUST be filled with zeros.
| Parameters  | `blockAddress` -- the address of the block to retrieve.
| Returns     | A `byte array` containing the block data; zero-filled if the block has not been read.
| Throws      | `IndexOutOfBoundsException` -- if the block address is out of range.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `getBlocks(fromBlockAddress: integer, toBlockAddress: integer) -> byte array`
| Description
| Returns the data blocks within the specified range from the memory image of the storage card. The returned
  array contains the blocks in order, from `fromBlockAddress` to `toBlockAddress` (both inclusive). Blocks that
  have not been previously read MUST appear as zero-filled sections.
| Parameters
| `fromBlockAddress` -- the starting block address (inclusive). +
  `toBlockAddress`   -- the ending block address (inclusive).
| Returns     | A `byte array` containing the data blocks in the specified range.
| Throws      | `IndexOutOfBoundsException` -- if `fromBlockAddress` is greater than `toBlockAddress`, if either is negative, or if they exceed the memory image range.
|===

| Throws

=== Package storagecard.transaction

[[type_StorageCardTransactionManager]]
==== StorageCardTransactionManager

[cols="1h,4", grid=rows, frame=ends]
|===
| Kind     | Interface
| Package  | `storagecard.transaction`
| Extends  | `CardTransactionManager<StorageCardTransactionManager>` ([CNA-TR-API])
| Purpose  | Manages APDU exchanges with a storage card. It allows the application to prepare read and write operations, batch them into a single transaction, and control the underlying communication channel.
|===

===== Behaviour of the inherited `processCommands()`

The inherited `processCommands()` operation MUST:

* send every APDU corresponding to a prepared command, in the order in which it was prepared;
* update the <<type_StorageCard,`StorageCard`>> memory image with the data retrieved from the card for read commands;
* update the <<type_StorageCard,`StorageCard`>> memory image with the data written for write commands, *only* when
  the write is confirmed successful. For card technologies that do not provide reliable status codes (e.g.
  ST25/SRT512), confirmation MUST be obtained via an automatic verification read; the memory image MUST be
  updated only if this verification passes;
* interrupt the process at the first failed command.

===== Operations

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareSt25ReadSystemBlock() -> StorageCardTransactionManager`
| Description | Prepares the reading of the system block of an ST25/SRT512 storage card.
| Returns     | The current instance.
| Throws      | `UnsupportedOperationException` -- if the current card type is not ST25/SRT512.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareSt25WriteSystemBlock(data: byte array) -> StorageCardTransactionManager`
| Description
| Prepares the writing of data to the system block of an ST25/SRT512 storage card. The data length MUST match the
  block size. The provided data MUST represent the *expected final state* of the system block. Because ST25/SRT512
  cards do not provide reliable status codes, the implementation MUST perform an automatic verification read and
  fail the transaction if the physical state does not match the provided data.
| Parameters  | `data` -- the data to be written to the system block (expected final state).
| Returns     | The current instance.
| Throws
| `IllegalArgumentException` -- if `data` is `null` or its length does not match the block size. +
  `UnsupportedOperationException` -- if the current card type is not ST25/SRT512.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareSt25WriteSystemBlock(data: byte array, idCommand: integer) -> StorageCardTransactionManager`
| Description
| Same as `prepareSt25WriteSystemBlock(data)` but attaches an application-supplied identifier to the prepared

  this specific command causes an exception to be raised.
| Parameters  | `data` -- the data to be written. + `idCommand` -- the application-supplied identifier of this command.
| Returns     | The current instance.
| Throws      | Same as `prepareSt25WriteSystemBlock(data)`.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareReadBlock(blockAddress: integer) -> StorageCardTransactionManager`
| Description | Prepares the reading of a specific block. Block addresses start at `0`; the maximum value is `getBlockCount() - 1`. Once processed, the result MUST be available in the <<type_StorageCard,`StorageCard`>>.
| Parameters  | `blockAddress` -- the address of the block to be read.
| Returns     | The current instance.
| Throws      | `IllegalArgumentException` -- if the block address is out of range.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareReadBlocks(fromBlockAddress: integer, toBlockAddress: integer) -> StorageCardTransactionManager`
| Description | Prepares the reading of a range of blocks. Once processed, the result MUST be available in the <<type_StorageCard,`StorageCard`>>.
| Parameters
| `fromBlockAddress` -- the starting block address (inclusive). +
  `toBlockAddress`   -- the ending block address (inclusive).
| Returns     | The current instance.
| Throws      | `IllegalArgumentException` -- if one of the arguments is out of range.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareWriteBlocks(fromBlockAddress: integer, data: byte array) -> StorageCardTransactionManager`
| Description
| Prepares the writing of one or more blocks starting from the specified block offset. The number of blocks
  written is determined by the length of `data` divided by the block size of the card.

  *Important:* the application is responsible for ensuring that the write operations are coherent with the target
  card's technology (e.g. OTP bits, counters). The provided data MUST represent the *expected final state* of the
  blocks after the write.

  For cards that do not provide reliable status codes, the implementation MUST perform an automatic verification
  read and fail the transaction if the physical state does not match the provided data.
| Parameters
| `fromBlockAddress` -- the offset at which the blocks are written. +
  `data`             -- the data to be written (expected final state).
| Returns     | The current instance.
| Throws      | `IllegalArgumentException` -- if `data` is `null` or its length is not a multiple of the block size.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareWriteBlocks(fromBlockAddress: integer, data: byte array, idCommand: integer) -> StorageCardTransactionManager`
| Description
| Same as `prepareWriteBlocks(fromBlockAddress, data)` but attaches an application-supplied identifier to the
  prepared command. The identifier MAY later be obtained via
  <<op_getIdCommand,`StorageCardException.getIdCommand`>> if this specific command causes an exception to be
  raised.
| Parameters
| `fromBlockAddress` -- the offset at which the blocks are written. +
  `data`             -- the data to be written. +
  `idCommand`        -- the application-supplied identifier of this command.
| Returns     | The current instance.
| Throws      | Same as `prepareWriteBlocks(fromBlockAddress, data)`.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareMifareClassicAuthenticate(blockAddress: integer, mifareClassicKeyType: MifareClassicKeyType, key: byte array) -> StorageCardTransactionManager`
| Description
| Prepares a Mifare Classic authentication command using the supplied 6-byte key. The authentication MUST apply to
  the entire sector containing the specified block address. Once authenticated, subsequent read and write
  operations within the same sector MAY be performed without re-authentication, until the card is removed or
  another sector is accessed.

  *Security note:* same caveat as for the equivalent operation on the selection extension; security-sensitive
  applications SHOULD use the `keyNumber` overload instead.
| Parameters
| `blockAddress`         -- the address of any block within the sector. +
  `mifareClassicKeyType` -- the type of key to use. +
  `key`                  -- the 6-byte key data.
| Returns     | The current instance.
| Throws
| `IllegalArgumentException` -- if the block address is out of range, or if the key is `null` or not exactly 6 bytes long. +
  `UnsupportedOperationException` -- if the current card type does not support authentication.
|===

[cols="1h,4", grid=rows, frame=ends]
|===
| Signature   | `prepareMifareClassicAuthenticate(blockAddress: integer, mifareClassicKeyType: MifareClassicKeyType, keyNumber: integer) -> StorageCardTransactionManager`
| Description | Prepares a Mifare Classic authentication command using a key referenced by its storage index in the reader's key storage.
| Parameters
| `blockAddress`         -- the address of any block within the sector. +
  `mifareClassicKeyType` -- the type of key to use. +
  `keyNumber`            -- the index of the key in the reader's key storage.
| Returns     | The current instance.
| Throws
| `IllegalArgumentException` -- if the block address is out of range, or if the key number is invalid. +
  `UnsupportedOperationException` -- if the current card type does not support authentication.

[[sec_behaviours]]
== Behavioural Requirements

. The application MUST select the card using the [CNA-TR-API] `CardSelectionManager` enriched with a
  <<type_StorageCardSelectionExtension,`StorageCardSelectionExtension`>> before instantiating a transaction manager.
. For card types where `ProductType.hasAuthentication()` returns `true`, every read or write operation targeting a
  protected sector MUST be preceded by a successful authentication.
. For card types where `ProductType.hasWriteAcknowledgment()` returns `false`, every write command MUST be followed
  by an automatic verification read; the in-memory image MUST be updated only when verification succeeds.
. The exceptions exposed by this specification MUST carry the block address involved in the error whenever it is
  available, so that the application can correlate failures with specific memory locations.
